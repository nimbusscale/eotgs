# House-Style Injection — Structure & Findings

Input notes for building the image-generation skill. Documents how the house
style is combined with a per-image prompt at generation time, the injection
algorithm, the prompt structure that was tested, and what the two test
generations confirmed.

> Supersedes the older `dev/illustrate-session-plan.md` and
> `dev/spike-character-consistency.md` for anything touching prompt structure /
> house style. Those are stale (earlier approach).

## Background / the decision this encodes

Illustrations are generated by sending a prompt document to OpenAI's image API
via `scripts/generate_image.py`. A canonical house style lives at
`config/image/house-style.json`.

The key architectural decision: **prompt files in `config/image/prompts/` do NOT
contain or restate the house style.** The house style is injected at generation
time by the skill, which combines house-style + reference prompt + per-image
details into one prompt before calling `generate_image.py`. The only
house-style-related content a prompt file carries is its *overrides* — captured
in an optional top-level `house_style_overrides` block. Everything generic
(medium, plate format, studio/scene lighting, tone, global avoids, default world
palette) was stripped from the prompt files and is supplied by injection.

All 26 prompt files have already been normalized to this convention (5 PC plates
converted from `.md` to `.json`, 21 scene/portrait JSONs slimmed in place).

## The house style: two layers

`config/image/house-style.json` has two layers plus authoring-only meta:

- **`GLOBAL_MEDIUM`** — rides on (almost) every image; the consistency anchor.
  Sub-keys:
  - `medium` — painterly-photoreal, documentary, grounded, anti-glamour. **Always inject.**
  - `format_for_plates` — full-body studio reference-plate framing (centered subject, seamless mid-gray backdrop, 2:3). **Plates only.**
  - `lighting_for_plates` — soft diffuse front studio light. **Plates only.**
  - `lighting_for_scenes` — diffuse atmospheric practical light, soft god-rays in sacred interiors. **Scenes only**, and only when the spec doesn't override lighting.
  - `tone` — grounded, candid, human-scale. **Always inject.**
  - `signature_items` — material-honest treatment of named gear. **Always inject** (cheap, harmless on scenes).
  - `avoid_global` — the global negative list (no glossy CGI, no movie-poster, no cinematic spotlighting on people, etc.). **Always inject.**
- **`WORLD_PALETTE`** — the default muted-earthy color/wear philosophy
  (`palette`, `wear_philosophy`, `tone_overlay`, `avoid_palette`). Injected as
  the default **only when the spec has no `palette` override.**
- **`_comment` / `_usage`** — authoring notes for humans/the injector. **Strip
  before sending to the image model.** (Also strip nested `_comment` keys inside
  `GLOBAL_MEDIUM` / `WORLD_PALETTE`.)

## The override block (in each prompt file)

A prompt file carries `house_style_overrides` **only when it deviates** from the
house style. Present on 12 of 26 files. Shape (include only the sub-keys that
apply):

```json
"house_style_overrides": {
  "palette": ["..."],            // replaces the muted WORLD_PALETTE entirely
  "palette_note": "Replaces the default muted WORLD_PALETTE with this canonical bright palette; do NOT mute, tarnish, or desaturate.",
  "signature_items": "...",      // only if the subject's signature gear overrides defaults
  "lighting": "...",             // only if this image overrides the default lighting
  "medium": "..."                // rare — only when the image overrides the medium itself (the map does this)
}
```

Notes from normalizing the files:
- A `palette` key signals "this subject is brighter/more luminous/more saturated
  than the muted default" (Roderic, the Chryseum interior/exterior, the renewal
  avatar, the dawn order, Severin, the Xan-Kor chamber, the map).
- `palette_note` is sometimes used *without* a `palette` key to flag a single
  luminous exception inside an otherwise-muted scene (e.g. `crest-aurelion-castle`
  keeps the whole scene muted but calls out the one bright dome) or to say
  "these colored accents are NOT a wholesale bright override" (`the-triune`).
- `lighting` overrides the default scene/plate lighting (Paxton's divine
  self-glow; the Chryseum's engineered two-temperature light; the avatar's
  self-emitted glow).
- `medium` is the rare, near-total override — `kingdom-of-beaconhold-map` uses it
  to swap the painterly-photoreal medium for antique cartography.
- Some files carry a small bespoke note key where it fit better than the
  standard schema (e.g. `the-clockworks-automaton` has a `wear_note` carving out
  "maintained/clean, overriding the default 'worn at working surfaces'" rule).
  The schema is intentionally loose — machine-readable, but not rigidly fixed.

## Injection algorithm

Given a prompt spec, build the injected `GLOBAL_MEDIUM` and decide whether to add
`WORLD_PALETTE`. This is the logic the two tests validated (Python-ish):

```python
def strip_meta(d):
    return {k: v for k, v in d.items() if not k.startswith("_")}

overrides = spec.get("house_style_overrides", {})
gm = strip_meta(house["GLOBAL_MEDIUM"])

# Always-on base.
global_medium = {
    "medium": gm["medium"],
    "tone": gm["tone"],
    "signature_items": gm["signature_items"],
    "avoid_global": gm["avoid_global"],
}

# Format + lighting depend on plate vs scene.
if is_plate(spec):
    global_medium["format_for_plates"] = gm["format_for_plates"]
    if "lighting" not in overrides:
        global_medium["lighting_for_plates"] = gm["lighting_for_plates"]
else:  # scene
    if "lighting" not in overrides:
        global_medium["lighting_for_scenes"] = gm["lighting_for_scenes"]

house_style = {"GLOBAL_MEDIUM": global_medium}

# World palette only when the spec doesn't replace it.
if "palette" not in overrides:
    house_style["WORLD_PALETTE"] = strip_meta(house["WORLD_PALETTE"])

# (If overrides["medium"] is set — the map — you may also drop GLOBAL_MEDIUM.medium
#  or let the override-replaces-default instruction handle it.)
```

Rules in plain language:
1. **Always inject** `GLOBAL_MEDIUM.medium`, `.tone`, `.signature_items`, `.avoid_global`.
2. **Plate vs scene picks the format/lighting field.** Plates get
   `format_for_plates` (+ `lighting_for_plates`); scenes get
   `lighting_for_scenes` and no plate format. Maps get neither (the map's
   `house_style_overrides.medium` governs).
3. **Inject `lighting_for_*` only if the spec has no `lighting` override.** An
   override replaces the default; injecting both invites contradiction.
4. **Inject `WORLD_PALETTE` only if the spec has no `palette` override.** When
   the spec overrides the palette, the muted default (including its
   `avoid_palette`) must be left out, or it will fight the bright override.
   - **Exception — character-in-scene (see Test 3).** When a strong-palette
     *character* is placed in a muted-world *scene*, inject BOTH: `WORLD_PALETTE`
     governs the environment, and the character's `palette` override is scoped to
     the figure. State the scoping explicitly in the header. The "palette
     override ⇒ suppress WORLD_PALETTE" rule is about whether the *whole image*
     is a bright subject (Chryseum); a bright character on a dark background is
     not — both palettes coexist, each scoped to its part of the frame.
5. **Strip `_comment` / `_usage`** (top-level and nested) before sending.

### Determining plate vs scene

The PC reference plates are the five `*-reference-plate-prompt.json` files; they
have `source_reconciliation` / `identity_lock` fields and no scene/architecture
fields. Scenes/portraits have `setting` / `architecture` / `composition` and a
scene `aspect_ratio`. For the skill, the cleanest signal is probably an explicit
`type` field on each spec (`plate` | `scene` | `portrait` | `map`) rather than
inferring — worth adding during skill dev.

## Prompt structure (what gets sent to the model)

The injected prompt is plain text with a short instruction header followed by two
labeled JSON blocks. `generate_image.py` accepts this via `--prompt-file` (a
`.txt` is sent as raw text; a `.json` is re-serialized whole). The tests wrote
the composed text to a temp `.txt` and passed `--prompt-file`.

Header (scene variant; adjust "SCENE" → "character reference plate" for plates):

```
Render a single campaign illustration (a SCENE / environment, not a character
plate). Apply the HOUSE STYLE below as the global rendering rules (medium,
[scene lighting,] material honesty, tone, and global avoids). Then render the
specific IMAGE SPEC. Where the image spec gives its own concrete details
(subject, setting, architecture, composition, scene color_palette,
image-specific negatives, aspect ratio), those take precedence over any
conflicting generic house-style default; otherwise the house style governs.

[IF the spec has a house_style_overrides block, add:]
IMPORTANT — this spec contains a "house_style_overrides" block. Those overrides
REPLACE the corresponding house-style defaults: the override palette replaces
the muted default world palette entirely (do NOT mute or tarnish this image),
and the override lighting replaces the default scene lighting. The medium, tone,
material honesty, and global avoids from the house style still apply.

=== HOUSE STYLE (global rendering rules) ===
{ ...injected house_style JSON (GLOBAL_MEDIUM [+ WORLD_PALETTE]) ... }

=== IMAGE SPEC ===
{ ...the full prompt spec JSON, including its house_style_overrides block... }
```

Two-block layout (house style first as global rules, then the image spec) read
cleanly for the model. Keeping the override block inside the IMAGE SPEC and also
naming it in the header (the IMPORTANT paragraph) reinforced that overrides win.

### Size / aspect

`generate_image.py` sizes: `--tall` 1024x1536, `--wide` 1536x1024, `--square`
1024x1024 (default `--wide`). Map the spec's `aspect_ratio` to a flag:
- `2:3 portrait` → `--tall`
- `16:9 landscape` / `3:2` → `--wide`
- square → `--square`

Use `--name <slug>` to control the output filename (otherwise a naming model
derives one and reprompts on collision). Output lands in `images/<name>.jpg`.

### Reference images (image-to-image) — separate endpoint

For "known character/place in a new situation," pass an existing image as a
likeness reference. This needs OpenAI's **`/v1/images/edits`** endpoint, which
`generate_image.py` does NOT currently support (it only calls
`/v1/images/generations`, text-to-image). Test 3 called `edits` directly:

```
curl -sS https://api.openai.com/v1/images/edits \
  -H "Authorization: Bearer $OPENAI_ACCESS_KEY" \
  -F "model=gpt-image-2" \
  -F "image[]=@images/pcs/roderic-pose.jpg;type=image/jpeg" \
  -F "prompt=</tmp/composed-prompt.txt" \
  -F "size=1536x1024" -F "quality=high" -F "n=1" -F "output_format=jpeg"
```

`image[]` may be repeated for multiple references (e.g. add `roderic-horse.jpg`
to help a mounted pose). Response is `data[0].b64_json` → decode to bytes. The
skill should grow an `--image`/reference-image path (extend `generate_image.py`
to branch to `edits` when references are supplied) plus a header instruction
telling the model the reference is the identity source.

## Test findings

Two end-to-end generations, one per injection path. Both rendered on-style and
on-spec. Test images were written beside the originals with a
`-housestyle-test` suffix (untracked scratch — delete after review).

### Test 1 — `aurelion-approach` (NO override path)
- Spec has no `house_style_overrides`, so `WORLD_PALETTE` was injected in full
  and plate fields were dropped (it's a scene).
- Result matched the original closely: tarnished green-gold dome (not bright),
  weathered limestone, road-dust cobbles, muted hillsides, overcast
  golden-hour; grounded painterly-photoreal, no cinematic gloss. All
  image-specific content (hilltop citadel, sunburst gatehouse, approach road,
  foreground waymarker stone, smallholdings, chimney smoke, scale figures)
  survived the strip-and-reinject.
- **Confirms:** the muted default correctly comes from injection, not the file.

### Test 2 — `chryseum-interior` (override path — the make-or-break test)
- Spec has `house_style_overrides` with `palette` + `lighting`. The injector
  **suppressed `WORLD_PALETTE`** and **dropped the default scene lighting**;
  `GLOBAL_MEDIUM` medium/tone/signature/avoids still rode.
- The prompt file itself no longer contains any palette/lighting prose — it
  lives only in the override block — yet the render came out fully luminous:
  fresh radiant gold dome, pale honey limestone, cool blue-white self-luminous
  whiteglass altar, engineered two-temperature light, incense haze in the
  shafts, candle-amber at human scale. Nothing tarnished or desaturated it.
- This is the critical check: if the override block hadn't carried the bright
  palette, dropping `WORLD_PALETTE` would have left the interior colorless. It
  didn't — the override supplied it. Image-specific content survived (entrance→
  altar single-point perspective, abstract sunburst dome, shadowed side
  colonnades, the pre-Luciferian spiral floor motif, small worshippers, no
  Christian iconography).
- **Confirms:** the override block correctly *replaces* the muted defaults, and
  the `WORLD_PALETTE`/`lighting` suppression logic is safe.

### Test 3 — Roderic on a dark forest road (character-in-scene + reference image)
Three new things at once: a named character placed in an ad-hoc scene, a
strong-palette character inside a muted-world environment, and a **reference
image** passed to OpenAI for likeness.

- **Reference image required the `/v1/images/edits` endpoint**, not
  `/v1/images/generations`. `generate_image.py` only does text-to-image, so this
  test called `edits` directly (multipart `image[]=@images/pcs/roderic-pose.jpg`
  + the composed text prompt; `model=gpt-image-2`, `size=1536x1024`,
  `quality=high`, `output_format=jpeg`; response `data[0].b64_json` decoded to
  `images/roderic-dark-forest-test.jpg`).
- **Injection used the character-in-scene shape:** `GLOBAL_MEDIUM`
  (medium/lighting_for_scenes/tone/signature/avoids) **+ `WORLD_PALETTE` for the
  environment** **+ Roderic's `house_style_overrides` scoped to the character.**
  Three content blocks: HOUSE STYLE, CHARACTER (the roderic plate spec, identity-
  matched to the reference image), SCENE (the ad-hoc forest/road/mounted spec).
  A dedicated **PALETTE SCOPING** paragraph in the header told the model: forest =
  muted world palette; Roderic = his bright override; do not mute the character.
- **Result:** identity preserved well (face, hair, silver-steel + gold filigree,
  blue surcoat, gold-lion kite shield); palette scoping nailed — dark, overgrown,
  threatening forest with Roderic and his white horse a bright point of light;
  light shafts through the canopy on the road; no monsters, no spell glow.
- **Confirms:** (a) reference-image likeness via `edits` works and is the right
  tool for "known character in a new situation"; (b) the dual-palette scoping
  (world for environment + character override for the figure) is a real, distinct
  injection mode the skill needs.
- **Watch:** the hero-light-through-canopy leaned slightly toward dramatic/heroic
  lighting (brushing `avoid_global`'s "no cinematic spotlighting on people"),
  though it stayed in the grounded painterly register. If the skill wants to hold
  that line harder on character-in-scene shots, reinforce the anti-spotlight
  avoid in the header.

### Test 4 — Four PCs planning in a busy tavern (multi-character group + multi-reference + mixed palette scoping)
The hardest case so far: four named characters in one scene, four separate
reference images, and three different palette statuses at once.

- **Four reference images** passed to `/v1/images/edits` (one per character:
  `castor-human.jpg`, `garland-portrait.jpg`, `roderic-pose.jpg`,
  `paxton-pose.jpg`). gpt-image-2 mapped each reference to the right character —
  all four came out recognizable (Garland even holding Second Harvest with its
  distinctive broad pattern-welded blade). One reference per character (not extra
  refs of one character) kept the head-count correct.
- **Mixed palette scoping in a single frame, all correct:**
  - Environment (tavern) + Castor + Garland → muted `WORLD_PALETTE`.
  - Roderic → his bright `palette` override (clearly brighter than the dim room
    and his travel-worn companions).
  - Paxton → muted register EXCEPT his `lighting` override (the gold face-marks
    glowing subtly).
  The header listed the scoping **per named character** (who is muted, who is
  bright, who has the lighting exception). That per-character enumeration is the
  pattern: for a group, walk each character and state its override status.
- **Result:** exactly four at the focal table, warm busy night tavern (hearth,
  crowd, serving figure, lanterns), map + tankards + candle, no spell glow, no
  cinematic spotlighting. Roderic stayed bright; the others stayed grounded.
- **Confirms:** the scoping rule generalizes from one character (Test 3) to N
  characters with mixed override status. The skill should, for a group spec,
  inject `WORLD_PALETTE` once for the environment + muted cast, then enumerate
  each character's override status in the scoping header.

### Net
Strip-and-reinject is sound across all four tested modes: no-override scene
(aurelion), override scene (chryseum), single character-in-scene with a
reference image (roderic forest), and a multi-character group scene with four
reference images and mixed palette scoping (tavern). The override-block shape
(`palette` / `palette_note` / `lighting` / `signature_items` / `medium`) held up
unchanged throughout — no schema changes were needed. The one mode still
untested is the **pure PC reference plate** (studio plate: strong-palette
override *plus* the `format_for_plates` / `lighting_for_plates` fields scenes
skip) — worth running once during skill dev, optionally with the plate image as a
reference to lock identity.

## Open questions / iteration notes for skill dev

- **Add an explicit `type` field** to each spec (`plate`/`scene`/`portrait`/`map`)
  so the skill doesn't infer plate-vs-scene from field presence.
- **Per-image details slot:** the original brief mentioned "house-style +
  reference prompt + per-image details." Test 3 demonstrated this with a third
  `=== SCENE ===` block of ad-hoc details after the CHARACTER block, with the
  "specific details take precedence" rule — that layout works. Formalize it: a
  reusable spec (character/place) + an ad-hoc per-generation block (the moment,
  setting, action, lighting tweak) is the general shape.
- **Reference-image support in `generate_image.py`:** add an `--image` path that
  switches to the `/v1/images/edits` endpoint (multipart, `image[]`) when one or
  more reference images are supplied. Today the script is generations-only. See
  the "Reference images" section above.
- **Character-in-scene palette scoping:** the skill must detect this mode (a
  strong-palette character spec combined with a scene) and inject BOTH the world
  palette (environment) and the character override (figure), with an explicit
  scoping paragraph. Don't reuse the pure-override suppression logic here.
- **Map / medium override:** `kingdom-of-beaconhold-map` overrides the medium
  itself. Confirm the skill drops `GLOBAL_MEDIUM.medium` (or trusts the
  override-replaces-default instruction) so the photoreal medium doesn't fight
  the cartographic one.
- **`signature_items` on scenes** is harmless but irrelevant — could be skipped
  for scenes to keep the prompt tighter.
- **Run the plate path test** (roderic) to confirm `format_for_plates` +
  strong-palette override compose correctly.
- **Reproducibility:** generations vary (framing/zoom). For acceptance, judge
  style/palette/content adherence, not pixel match.
